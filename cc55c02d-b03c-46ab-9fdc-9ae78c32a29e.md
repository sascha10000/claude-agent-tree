**No sorting or grouping.** Projects by newest-session mtime (`index.rs:72-77`), sessions by mtime desc (`index.rs:95`) — hard-coded. No sort by cost/size/duration, no global cross-project session view, no date grouping.

## Ordering rationale & cross-cutting risks

- 1 → 2 build the overlay infra in increasing complexity; 3 depends on nothing from 2 but shares the spawn-record extension mindset; 4 needs `started/finished` on `FlatAgentRow` added in 3; 5 is fully independent and riskiest terminal-wise, so it goes last.
- **Serde renames**: `totalAPIDuration` and `costUSD` need explicit `rename` (the file's casing defeats `rename_all = "camelCase"`) — the existing `totalCostUSD` comment at model.rs:67 is the precedent.
- **Lazy re-read correctness**: append-only files keep spans valid; the only invalidation is a file rewrite (shrink), which `refresh` already detects and which triggers full re-parse → spans recomputed. The popup reads a snapshot at open; failures degrade to capped in-memory content, never garbage.
- **`Enter` overload** in the timeline: preserved cross-jump for spawn events, popup otherwise, `o` always popup — zero behavior regression.
- **Suspend/restore**: the input-thread contention fix (poll + suspend flag) is the part most likely to bite; test the error path explicitly.

### Race analysis

1. **Data race: none.** The worker owns its `LoadedSession` exclusively until it is moved through the channel; `App` is only ever touched on the event-loop thread. Pure message passing, no locks.
2. **`refresh_loaded` vs. in-flight load:** while loading, `self.loaded` is still `None` (we stay in Browse), so `refresh_loaded` (app.rs:409) no-ops and `path_touches_loaded` (app.rs:428) returns false — Fs events during the load only `rescan_index`, which is safe. The gap — bytes appended to the target file *during* the parse that produced the sent snapshot — is closed by the `self.refresh_loaded()` call in `finish_load`: `refresh()` is incremental via stored offsets (session.rs:115), so this costs only the appended bytes.
3. **Stale results:** user presses Enter on session B while A is loading → `loading = Some(B)`; A's `Loaded` arrives, id mismatch, dropped on the floor (the boxed session is just freed). Matching on **id**, not a generation counter, is sufficient because re-opening the *same* id is idempotent (the double-enter guard prevents duplicate workers for one id).
4. **Resume drain:** `resume_session` drains the channel after the child exits (main.rs:88), which could swallow a `Loaded` event whose worker finished while the TUI was suspended — and its id may *equal* `app.loading`. Fix: in `event_loop`, before the drain, set `app.loading = None` (the reload at main.rs:126 rebuilds state anyway); any late `Loaded` then fails the `finish_load` id check. One line, mention in a comment.
5. **Quit while loading:** worker's `tx.send` returns `Err` after `rx` drops; result discarded, thread exits. `main` returning doesn't join it — acceptable (same as the input thread today), the process teardown reaps it.

## F — Background session loading (riskiest, last)

### Design: worker thread + new AppEvent, App holds a Sender clone

**watch.rs** — extend the enum:

```rust
pub enum AppEvent {
    Input(crossterm::event::Event),
    Fs(Vec<PathBuf>),
    Loaded(Box<std::io::Result<LoadedSession>>),   // boxed: LoadedSession is large
}
```

(`Box<io::Result<..>>` keeps the enum small; the id for staleness checks is readable from `session.meta.id` on Ok — for the Err case we also need the id, so make it `Loaded { id: String, result: Box<std::io::Result<LoadedSession>> }`.)

**Plumbing:** `App` gets `pub tx: Option<Sender<AppEvent>>` (Option so tests and `--dump` construct App-free/synchronously) and `pub loading: Option<String>` (the session id in flight). `run_tui` (main.rs:54) sets `app.tx = Some(tx.clone())` after creating the channel — note `tx` is currently moved into `spawn_watcher` (main.rs:53); clone before.

**app.rs `open_selected_session` (app.rs:347-365)** becomes:

```rust
pub fn open_selected_session(&mut self) {
    ... resolve meta as today ...
    match &self.tx {
        Some(tx) => {
            self.loading = Some(meta.id.clone());
            self.status_msg = Some(format!("loading {}…", meta.id[..8]));
            let tx = tx.clone();
            std::thread::spawn(move || {
                let id = meta.id.clone();
                let result = LoadedSession::load(meta);
                let _ = tx.send(AppEvent::Loaded { id, result: Box::new(result) });
            });
        }
        None => self.finish_load(LoadedSession::load(meta)), // sync fallback (tests)
    }
}
```

`fn finish_load(&mut self, result: io::Result<LoadedSession>)` holds the exact body of today's `match LoadedSession::load(meta)` arms (set agent_rows/view/focus/etc. or status_msg).

**main.rs `handle_event`** — new arm:

```rust
AppEvent::Loaded { id, result } => app.on_loaded(id, *result),
```

`App::on_loaded`: if `self.loading.as_deref() != Some(&id)` → stale (user opened something else, or pressed Esc… see below) → drop silently. Else `self.loading = None; self.status_msg = None; self.finish_load(result)`.

### Race analysis

1. **User opens session B while A is loading.** `loading` is overwritten with B's id; A's `Loaded` arrives, id mismatch, dropped. B wins. Two threads may run concurrently — both are read-only over distinct files; fine. Guard against double-spawn for the *same* id: at the top of `open_selected_session`, `if self.loading.as_deref() == Some(&meta.id) { return; }` (user mashing Enter).
2. **Fs event during in-flight load → `refresh_loaded`.** `refresh_loaded` (app.rs:408) early-returns when `self.loaded` is `None`, and `loaded` isn't set until `finish_load`. But if the user had a session open in Detail and (impossible today — opening requires Browse) — actually `open_selected_session` is only reachable from Browse, where `loaded` is `None` (Esc from Detail clears it, app.rs:250-256). So `refresh_loaded` can't race the load through app state. The worker's `LoadedSession::load` reads files that the running `claude` may append to concurrently — already true today for `refresh()`; JSONL append + offset tracking tolerates torn tails (parse_errors, and the shrink check at session.rs:130-135). No shared mutable state: the worker owns `meta` and the new `LoadedSession` until it's sent. **No lock needed.**
3. **`pending_resume` while loading:** `R` is Browse-only and doesn't touch `loaded`; after resume, `app.reload()` runs `rescan_index`+`refresh_loaded` — safe per (2). A stale `Loaded` arriving after resume for a still-matching id is *not* stale-by-id; it will open the Detail view post-resume. That's arguably correct (user asked for it); if undesired, clear `self.loading = None` in `resume_session`'s event-drain (main.rs:88) — recommend doing that for predictability.
4. **Quit while loading:** worker's `tx.send` fails after `rx` drops; thread exits; detached thread at process exit is fine.
5. **Cancel:** Esc in Browse doesn't cancel; add `Esc` clears `self.loading` (and status_msg) if set — cheap cancellation via staleness.

**Spinner:** the 1s `recv_timeout` tick redraws anyway; `status_msg = "loading <id>…"` in the (red) status bar is sufficient for v1 — a Braille spinner needs a tick counter field (`app.tick: usize` incremented on timeout) — optional polish, skip.

**Keep `--dump`/`--export` synchronous:** they never construct an `App`, so they call `LoadedSession::load` directly — unchanged.

**Verify:** unit tests: (a) `on_loaded` with mismatched id leaves state untouched; (b) matching id sets `view = Detail`; (c) double-Enter doesn't spawn twice (assert loading unchanged — testable by checking `open_selected_session` early-return with a stub `tx` from `mpsc::channel()` and counting `rx` after; or keep `tx: None` and test the guard logic separately). Real-data smoke: open the 48MB session — UI stays responsive, statusbar shows loading, Detail appears; open it and immediately open a small session — small one wins.
